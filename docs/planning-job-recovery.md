# Planning controls, reconnecting jobs and manual destinations

Optimization runs durably on the server. Closing a browser does not cancel it. Explicit Stop revokes its lease/fence through the existing tenant-authorized API; stale workers still cannot publish. The user can navigate while work runs, then Open or Stop it from the background-work bar. The current plan remains unchanged until candidate adoption.

The Stop control is independent of permission to edit or submit new optimization. A stale workspace must not hide the ability to cancel an already-known job. Reviewer remains read-only. A transient failed freshness check pauses editing, but a later successful check of the same revision restores it. A genuine revision conflict still requires a refreshed workspace.

Browser references survive navigation and transient request errors. If a tab disappears before recording its submission response, the authenticated API can discover active solves submitted by that actor, scoped to the deployment tenant. Jobs created before actor attribution remain shared within that tenant; they are never exposed across tenants or falsely attributed to one user. Discovery returns only job/context metadata, not complete request payloads. Results that completed without a retained browser reference remain in Plans. This is discovery of durable work, not automatic cancellation on disconnect.

Manual assignment no longer requires dragging to a long vehicle list or opting into a global mode first: select an order and use Move to vehicle / Assign to vehicle. Existing solver preferences remain available under their own disclosure. Search narrows the vehicle list by registration or class. The dialog identifies vehicle, round, time span, stop count and insertion position; it shows the destination round's current stops/load before the move. Those are current values, not a feasibility certificate. Preview still recalculates the complete draft, KPIs and constraints before saving.

A direct move starts from the order's current vehicle/round. A vehicle with multiple rounds requires an explicit choice when changing vehicles or dragging to a vehicle; the last round is never silently selected. New round is distinct from an existing round. Unavailable, excluded and locked target vehicles cannot be selected. Server-side validation and immutable dataset identities remain authoritative. Bulk edits retain the existing stable request-ID commands and insertion semantics. Manual versus automatic assignment history is preserved.

Regression coverage includes browser-reference loss, navigation while work is active, Stop after freshness failure, recovery of reordering, explicit vehicle/round selection, tenant/actor discovery, and native cancellation after closing/reopening a page. No production jobs are cancelled by the tests.
